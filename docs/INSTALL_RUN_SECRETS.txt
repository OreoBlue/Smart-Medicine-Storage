PANDUAN INSTALASI, SECRETS, DAN DEPLOYMENT
SMART STORAGE ROOM MONITORING — KELOMPOK 3
============================================================

TUJUAN
- Wokwi mensimulasikan sensor DHT22, LDR, sakelar pintu, dan aktuator.
- Firebase Realtime Database menyimpan /telemetry serta /event_logs.
- Dashboard Streamlit hanya membaca dua path tersebut. TIDAK ada fungsi kontrol dari dashboard.
- "Demo Lokal" = data contoh/sintetis, TIDAK menghubungi Firebase.
- "Firebase Live" = pembacaan Firebase terautentikasi menggunakan Anonymous Authentication.

0. AMANKAN PROJECT DAN REPOSITORY
------------------------------------------------------------
- JANGAN masukkan API token Firebase ID/refresh token, password, atau private key ke GitHub.
- API key Web Firebase boleh digunakan sebagai identifier proyek, tetapi tetap letakkan bersama
  refresh token di Streamlit Secrets supaya tidak tersebar secara tidak sengaja.
- Jika pernah membagikan database secret lama, cabut/rotasi dulu.
- Jangan unggah file .streamlit/secrets.toml ke GitHub.
- Wokwi yang dibagikan secara PUBLIK tidak boleh mengandung refresh token device aktif.
  Gunakan proyek demo terpisah atau cabut token sebelum mempublikasikan salinannya.

1. SIAPKAN FIREBASE
------------------------------------------------------------
1) Buka https://console.firebase.google.com/
2) Pilih proyek Firebase kelompok: iotkel3-4c1aa
3) Build -> Realtime Database -> tab Data.
   Salin Database URL yang BENAR dari console. Contoh yang teridentifikasi di kode sumber:
   https://iotkel3-4c1aa-default-rtdb.firebaseio.com
   JANGAN berasumsi URL contoh selalu sama dengan project/region saat ini.
4) Buka Authentication -> Sign-in method -> Anonymous -> Enable -> Save.
5) Cari WEB API KEY dari Project settings -> General.
6) Di lokal, jalankan:
   python -m pip install requests
   python tools/create_anonymous_accounts.py
   Masukkan Web API Key ketika diminta (input tidak ditampilkan).
7) Script membuat DUA akun anonim dengan UID dan refresh token terpisah:
   A. WOKWI_DEVICE: UID_DEVICE + REFRESH_TOKEN_DEVICE
   B. STREAMLIT_READER: UID_READER + REFRESH_TOKEN_READER
   Simpan di tempat pribadi, jangan kirim ke grup umum, screenshot, atau GitHub.
   Penting: bukan membuat akun anonim baru setiap kali aplikasi Streamlit dijalankan.
8) Realtime Database -> Rules: buka firebase/rules.example.json.
   Ganti ISI_UID_DEVICE_WOKWI dengan UID WOKWI_DEVICE.
   Ganti ISI_UID_READER_STREAMLIT dengan UID STREAMLIT_READER.
   Publish Rules. Rules membatasi READ dashboard dan WRITE device secara terpisah.
9) Di Database -> Data, pastikan /controls sudah terisi:
   { "mode": "AUTO", "manual_cooler_req": false, "inject_sensor_fault": false }
   Huruf besar "AUTO" dianjurkan; ekspor lama punya "Auto" yang bisa tidak dikenali
   oleh beberapa firmware. Dashboard sendiri TIDAK membaca /controls.
10) Jika memakai Rules yang aman, sketch Wokwi LAMA dengan FIREBASE_AUTH="" tidak akan
    bisa mengirim telemetry. Gunakan firmware referensi anonim terpisah pada langkah 2,
    atau tambahkan mekanisme ID token sesuai Security Rules.

2. WOKWI (MEMASTIKAN DATA SUMBER MENGALIR)
------------------------------------------------------------
- Buat / buka proyek ESP32 di https://wokwi.com/
- File referensi kompatibel disediakan pada folder wokwi_reference/:
  sketch.ino, diagram.json, libraries.txt, secrets.h.example.
- File diagram.json disesuaikan dengan pin dari kiriman terakhir:
  GPIO4 DHT22; GPIO34 LDR; GPIO32 pintu; GPIO33 tombol gangguan;
  GPIO26 pendingin; GPIO25 LED alarm; GPIO27 buzzer.
- Buat file secrets.h (tanpa akhiran .example) di Wokwi:

    #pragma once
    #define FIREBASE_DATABASE_URL "https://iotkel3-4c1aa-default-rtdb.firebaseio.com"
    #define FIREBASE_API_KEY "ISI_WEB_API_KEY_FIREBASE"
    #define FIREBASE_DEVICE_REFRESH_TOKEN "ISI_REFRESH_TOKEN_DEVICE_ANONIM"

  Dua string terakhir diganti kredensial asli milik WOKWI_DEVICE, BUKAN akun reader.
- Start Simulation, lihat Serial Monitor.
- Pastikan ada [AUTH] Anonymous device token refreshed.
- Pastikan /telemetry berubah di Firebase. Contohnya:
  temperature, humidity, light_pct, door_open, cooler_on, state,
  timestamp_ms (UPTIME), updated_at (server timestamp jika firmware referensi dipakai).
- Penting: bagian firmware referensi disediakan untuk pengujian kompatibilitas dan belum
  dikompilasi di Wokwi dalam lingkungan pembuatan paket ini. Apabila compiler menunjukkan
  error, kirim pesan "error:" pertama dan versi library Wokwi agar dapat ditelusuri.
- Sensor dan aktuator hanyalah simulasi, LED biru bukan alat pendingin fisik.
- Data telemetri merupakan snapshot terbaru, bukan histori penuh.

3. MENJALANKAN STREAMLIT DI LAPTOP
------------------------------------------------------------
A. Ekstrak ZIP paket ini lalu buka folder project (folder yang berisi app.py).
B. Install Python 3.10+.
C. Di PowerShell/CMD/Terminal jalankan:

    python -m venv .venv

   Windows PowerShell:
    .venv\\Scripts\\Activate.ps1
   Windows CMD:
    .venv\\Scripts\\activate.bat
   macOS/Linux:
    source .venv/bin/activate

D. Install dependensi:
    python -m pip install -r requirements.txt

E. Buat file .streamlit/secrets.toml dengan isi:

    [firebase]
    database_url = "https://iotkel3-4c1aa-default-rtdb.firebaseio.com"
    api_key = "ISI_WEB_API_KEY_FIREBASE"
    refresh_token = "ISI_REFRESH_TOKEN_READER_ANONIM"

   Ini adalah akun STREAMLIT_READER, bukan akun Wokwi.
   Jangan tulis UID, ID token, API key, atau refresh token asli di README atau berkas GitHub.
   .streamlit/secrets.toml sudah dikecualikan oleh .gitignore.

F. Jalankan:
    python -m streamlit run app.py

G. Browser biasanya terbuka di http://localhost:8501
H. Pilih sumber "Demo Lokal" (bisa tanpa Firebase).
I. Pilih "Firebase Live" setelah Wokwi dan Firebase berhasil tersambung.
J. Pilih tema Terang/Gelap di sidebar (pengaturan hanya untuk tampilan).
K. Dashboard REFRESH setiap ~3 detik, hanya GET data. Tidak ada tombol pengendali.

4. UPLOAD KE GITHUB
------------------------------------------------------------
1) Buat repo baru, contoh: smart-storage-kelompok-3-monitoring.
2) Ekstrak ZIP paket final, upload ISI folder ke root repository.
   Pastikan app.py dan requirements.txt ada di root, bukan berada dalam ZIP kedua.
3) Jangan upload .streamlit/secrets.toml ataupun output script create_anonymous_accounts.py.
4) Upload README.md, src/, tests/, docs/, firebase/, data/, wokwi_reference/,
   .streamlit/config.toml, .streamlit/secrets.toml.example, requirements.txt.
5) README.md menjadi tampilan dokumentasi utama di GitHub.

5. DEPLOY KE STREAMLIT COMMUNITY CLOUD
------------------------------------------------------------
1) Akses https://share.streamlit.io/
2) New app -> pilih repo GitHub kelompok.
3) Main file path: app.py
4) Settings / Advanced settings -> Secrets, isi TOML sama seperti pada langkah 3E.
   Jangan menaruh tanda ``` di field Secrets (cukup isi TOML murni).
5) Deploy.
6) Buka URL *.streamlit.app yang diberikan.
7) Coba DEMO LOKAL lebih dahulu.
8) Jalankan simulasi Wokwi (ESP32), lihat /telemetry di Firebase, pilih FIREBASE LIVE.
9) Perhatikan status "DATA MENGALIR" setelah heartbeat/timestamp teramati.
10) Untuk video demo, rekam Wokwi, Firebase Console, lalu Streamlit secara berurutan.

6. TROUBLESHOOTING
------------------------------------------------------------
- DEMO LOKAL bisa tampil, FIREBASE LIVE blank:
  cek Secret keys, Anonymous Auth, UID reader, Database URL, dan Security Rules.
- HTTP 403:
  UID reader belum diizinkan .read pada /telemetry atau /event_logs.
- HTTP 401:
  refresh token invalid/revoked, atau login ID token gagal.
- Failed to sign in / OPERATION_NOT_ALLOWED:
  Anonymous Authentication belum diaktifkan.
- Firebase /telemetry kosong:
  Wokwi belum menulis, URL berbeda, Wokwi berhenti, atau izin WRITE device ditolak.
- Firebase /controls/mode = "Auto":
  setel "AUTO" pada Console. Dashboard tidak membaca /controls.
- Status "MENUNGGU PEMBARUAN" pertama kali:
  wajar, snapshot tunggal belum membuktikan perangkat online.
- Status "DATA LAMA":
  timestamp_ms tidak berubah sekitar 15 detik; cek Wokwi atau Firebase.
- Grafik tidak menampilkan data masa lalu:
  firmware PUT /telemetry yang sama berulang kali, sehingga Firebase tidak menyimpan
  histori pengukuran; grafik mengumpulkan pembacaan selama Streamlit dibuka saja.
- Event "Waktu server" tampak "—":
  ekspor lama hanya punya timestamp_ms berupa uptime ESP32 (bukan epoch).
- Abaikan perintah kontrol dari dashboard:
  memang sengaja tidak disediakan. Pengendalian hanya melalui Wokwi/Firebase Console.
